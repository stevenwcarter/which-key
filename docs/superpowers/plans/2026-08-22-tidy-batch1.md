# tidy batch 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply 33 of the 35 style-and-structure findings from the 2026-08-22 `/tidy` triage — strengthening the lint config, de-duplicating logic shared between the React and vanilla renderers, splitting oversized functions, and fixing three small behavior bugs — without changing observable behavior except where a finding explicitly says so.

**Architecture:** Six sequential milestones, ordered so that each one's output is available to the next: toolchain/lint config first (so the stronger rules guard every later refactor), then the `keys.ts` canonicalization funnel, then the engine controller/registry, then the shared cross-renderer extractions, then the renderer cleanups that consume them, then docs. One task per finding, one commit per task, each commit also stripping its finding from `TIDY.md`.

**Tech Stack:** TypeScript 5.7 (strict, `noUnusedLocals`/`noUnusedParameters`), Vitest 2 + Testing Library + jsdom, ESLint 9 flat config + typescript-eslint 8, Prettier 3, tsup (dual ESM/CJS + `.d.ts`), husky + lint-staged + commitlint, Node ≥ 20.

**Spec:** `docs/superpowers/specs/2026-08-22-tidy-batch1-design.md` — read it alongside this plan. It carries the two design decisions (D1, D2) and the seven invariants this work refactors across.

**Baseline:** branch `tidy/2026-08-22` at commit `34dd498` (`docs: apply doc-comment updates`). All line numbers in this plan were re-derived against that commit, **not** against the stale numbers in `TIDY.md` (which were captured at `e3f3360`, before 343 lines of TSDoc landed).

## Global Constraints

Every task's requirements implicitly include this section.

**Commit convention — read this first.** The `/tidy` skill's own `tidy(<lens>): …` format is
**rejected by this repo**: `commitlint.config.js` extends `@commitlint/config-conventional`,
whose `type-enum` is `[build, chore, ci, docs, feat, fix, perf, refactor, revert, style, test]`.
The `commit-msg` hook is never bypassed and `--no-verify` is forbidden. This plan therefore
keeps the tidy lens as the Conventional-Commits **scope** and uses an allowed **type**:

| Kind of change             | Type used          | Example                                                                  |
| -------------------------- | ------------------ | ------------------------------------------------------------------------ |
| tooling, deps, lint config | `chore(<lens>)`    | `chore(idioms): enable type-aware linting [T3]`                          |
| pure restructuring         | `refactor(<lens>)` | `refactor(long-methods): extract parseModifiers from parseKey [T10]`     |
| behavior fix               | `fix(<lens>)`      | `fix(opportunistic): treat AltGraph as a modifier-only keydown [T8]`     |
| documentation              | `docs(<lens>)`     | `docs(comments): correct stale synthetic-event claim in CLAUDE.md [T35]` |
| characterization tests     | `test:`            | `test: characterize registry resolution before tidy [T15]`               |

All 35 commit messages in this plan (subject **and** body) were validated by piping them
through `npx commitlint`. Deliberately **not** done: widening `type-enum` to admit `tidy`.
`commit-and-tag-version` derives releases from these types, and `fix(opportunistic)` for the
AltGr bug is both semantically correct and changelog-worthy.

- **Subject ≤ 100 chars; every body line ≤ 100 chars** (commitlint `header-max-length` /
  `body-max-line-length`). Keep bodies hard-wrapped.
- **Never `--no-verify`.** The `pre-commit` hook runs `lint-staged` (prettier `--write` on
  staged files, then re-stages). A reformatted-on-commit file is expected, not a failure.

**Strip-on-fix (non-negotiable).** Every task's commit must ALSO delete that finding's whole
`### T<n>. …` block from `TIDY.md` — through its `- [x] execute   [ ] skip` line — and stage
`TIDY.md`. `TIDY.md` is currently untracked; the first `git add TIDY.md` begins tracking it,
which is intended. When the batch is done `TIDY.md` must contain exactly **T13 and T30**.

**Test rules.**

- **Do not refactor existing tests.** Adding new cases or new test files is expected and
  encouraged. The one exception is `src/engine/__tests__/types.test.ts` in Task 21, where a
  `toMatchTypeOf` shape assertion must mirror the `readonly` change to compile at all — that
  is a compile necessity, not a refactor.
- Run a subset with `npx vitest run <path>`, **never** `npm test` — coverage is configured
  `all: true` over `src/**`, so a partial run trips the 80% thresholds.
- `npm test` (full, with coverage) at every milestone boundary. Baseline: **381 tests**.

**Architectural invariants (full detail in the spec).**

- `src/engine/` stays free of framework dependencies.
- **Nothing new may be added to any `index.ts` public export surface** — that is a
  public-API change, which is disabled by default. `tsup.config.ts` uses an explicit 3-key
  `entry` map, so new shared modules do not become entry points.
- `parseKey`/`eventToCanonical` must produce byte-identical canonical strings.
- `getSnapshot()` must return a cached object; SSR fallbacks must be a single hoisted
  object, never a fresh literal.
- Both renderers emit the same `wk-*` class names; React hardcodes the `wk-` prefix while
  only `mountWhichKey` accepts `classPrefix`. Preserve that asymmetry.
- Anything public also goes in `docs/API.md` in the same commit.

**Out of scope.** The five open `decision-needed` markers in `bughunt.md` — cheatsheet
modality / Escape double-handling, unsilenceable `console.warn` diagnostics, React
portalling, `SPECIAL_KEYS` double duty (B48), B41, B49. Several tasks touch adjacent code
and say so; none may be extended into those decisions. Specifically: Task 13 must not become
an `onWarn` sink, Task 22 must not touch Escape handling, and Task 19 must not fix T30.

**Verification.**

- Per task: `npm run lint` and `npm run typecheck` clean.
- Per milestone: `npm test` green.
- Final: `npm run lint && npm run typecheck && npm test && npm run build && npm pack --dry-run`
  plus `npm run format:check`.

// Both buckets keep entries in ascending priority order, inserting BEFORE the
// first strictly-higher-priority entry. That insertion point is what makes
// "latest registration wins at equal priority" true, because findActive and
// getActiveGroup tiebreak on bucket index. Shared so the shortcut and group
// paths cannot drift apart.
const insertByPriority = <T extends { priority: number }>(
  map: Map<string, T[]>,
  key: string,
  entry: T,
): void => {
  const bucket = map.get(key) ?? [];
  const insertIndex = bucket.findIndex((e) => e.priority > entry.priority);
  bucket.splice(insertIndex === -1 ? bucket.length : insertIndex, 0, entry);
  map.set(key, bucket);
};

// Returns whether an entry was actually removed, so a caller can avoid
// bumping a mutation counter for an unregister that found nothing.
const removeById = <T extends { id: string }>(map: Map<string, T[]>, id: string): boolean => {
  for (const [key, bucket] of map) {
    const idx = bucket.findIndex((e) => e.id === id);
    if (idx >= 0) {
      bucket.splice(idx, 1);
      if (bucket.length === 0) map.delete(key);
      return true;
    }
  }
  return false;
};

- [ ] **Step 4: Add `pickBest`**

Insert in `src/engine/registry.ts` directly after `removeById` (added by Task 18):

```ts
// The winner cascade both resolvers share: level, then priority, then latest
// registration (higher bucket index).
//
// The `eligible` predicate is deliberately a parameter and the two callers
// pass DIFFERENT predicates — they are not interchangeable. A shortcut must
// be enabled AND either global or at/above the exclusive-layer floor; a group
// has neither an `enabled` nor a `global` field and is eligible purely on
// level. Collapsing them would silently hand groups a `global` escape hatch
// they do not have. That asymmetry is TIDY's T30, an open question that is
// deliberately NOT resolved here.
const pickBest = <T extends { level: number; priority: number }>(
  bucket: T[],
  eligible: (e: T) => boolean,
): T | undefined => {
  let best: T | undefined;
  let bestIdx = -1;
  for (let i = 0; i < bucket.length; i++) {
    const e = bucket[i];
    if (!eligible(e)) continue;
    if (
      best === undefined ||
      e.level > best.level ||
      (e.level === best.level && e.priority > best.priority) ||
      (e.level === best.level && e.priority === best.priority && i > bestIdx)
    ) {
      best = e;
      bestIdx = i;
    }
  }
  return best;
};
```

// The pure-DOM half of the cheatsheet's modal behaviour, shared by both
// renderers. It was previously duplicated character-for-character in
// src/react/ShortcutCheatsheet.tsx and src/vanilla/cheatsheet.ts, and the two
// copies had already begun to drift.
//
// Lives under src/shared/ rather than src/engine/ (which stays DOM-light) and
// is deliberately NOT re-exported from any index.ts, so it is internal.
//
// Scope: Tab handling only. Each renderer keeps its own Escape listener —
// cheatsheet modality / Escape double-handling is an open decision recorded in
// bughunt.md and is not settled here.

/** Elements the Tab trap treats as focus stops inside the cheatsheet panel. */
export const FOCUSABLE_SELECTOR =
  'button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])';

/** `id` of the cheatsheet heading; both renderers aim `aria-labelledby` at it. */
export const CHEATSHEET_TITLE_ID = 'wk-cheatsheet-title';

/**
 * Cycles Tab focus inside `panel`, wrapping at both ends. A no-op for every key
 * other than `Tab`, so a renderer can hand it any keydown. With no focusable
 * descendants it parks focus on the panel itself so focus cannot escape.
 */
export const trapTab = (panel: HTMLElement, e: KeyboardEvent): void => {
  if (e.key !== 'Tab') return;
  const items = Array.from(panel.querySelectorAll<HTMLElement>(FOCUSABLE_SELECTOR));
  if (items.length === 0) {
    e.preventDefault();
    panel.focus();
    return;
  }
  const first = items[0];
  const last = items[items.length - 1];
  const active = document.activeElement;
  if (e.shiftKey && (active === first || active === panel)) {
    e.preventDefault();
    last.focus();
  } else if (!e.shiftKey && active === last) {
    e.preventDefault();
    first.focus();
  }
};
```

import { useEffect, useSyncExternalStore } from 'react';
import { warnNoProvider } from './context';
import type { WhichKeyEngine, WhichKeySnapshot } from '../engine';

// Hoisted, never a per-call literal: useSyncExternalStore compares the
// getSnapshot result by identity and re-renders forever if a fresh object comes
// back each time. This is the no-provider / server fallback for every renderer.
const EMPTY: WhichKeySnapshot = {
  popup: { visible: false, currentSequence: [], candidates: [] },
  cheatsheet: { visible: false },
};
const noopSubscribe = () => () => {};
const getEmptySnapshot = () => EMPTY;

/**
 * Subscribes to `engine` through `useSyncExternalStore`, falling back to a
 * stable empty snapshot with no engine — during server rendering, or below no
 * `<WhichKeyProvider>` — instead of throwing. `what` only names the caller in
 * the missing-provider warning, which is emitted from an effect so the server
 * stays silent.
 */
export const useEngineSnapshot = (
  engine: WhichKeyEngine | null,
  what: string,
): WhichKeySnapshot => {
  useEffect(() => {
    if (!engine) warnNoProvider(what);
  }, [engine, what]);
  return useSyncExternalStore(
    engine ? engine.subscribe : noopSubscribe,
    engine ? engine.getSnapshot : getEmptySnapshot,
    getEmptySnapshot,
  );
};
```

// re-exported from src/vanilla/index.ts, so no public-API change.

// Every helper writes textContent, never innerHTML — the project's consistent
// choice, kept deliberate by routing element creation through one place.

/** Creates an element, sets its class, and optionally its text. */
export const el = <K extends keyof HTMLElementTagNameMap>(
  tag: K,
  className: string,
  text?: string,
): HTMLElementTagNameMap[K] => {
  const node = document.createElement(tag);
  node.className = className;
  if (text !== undefined) node.textContent = text;
  return node;
};

/** A `<kbd>` key cap under the caller's class prefix. */
export const kbd = (p: string, text: string): HTMLElement => el('kbd', `${p}-kbd`, text);

    li.appendChild(row(p, c));
